# SPECIFICATION — Sweeep

Версия: 0.2 · Дата: 2026-10-19
Название: **Sweeep** (логотип: SW**EEE**P, три растянутые «E»). UI приложения на английском; документация на русском.

## 1. Принципы

1. **100% локально.** Анализ, группировка, обработка медиа без AI/LLM/внешних API. Только детерминированные алгоритмы: хэши, метаданные, эвристики, классическое CV.
2. **Нулевая передача медиа.** MVP не требует интернета (кроме магазина подписок).
3. **Безопасное удаление.** Всё идёт через «мягкую» корзину приложения и системное подтверждение. Ничего не удаляется автоматически.
4. **Масштаб.** 50k–100k+ файлов; UI не блокируется, скан возобновляем.

## 2. Дизайн-направление

Прототипы: артефакт «Sweeep» (канвас, 8 экранов). Исходники экранов — HTML-прототипы в артефакте.

### 2.1 Палитра («Obsidian + Lavender»)
| Роль | Цвет |
|---|---|
| Фон | `#0F1015` |
| Карточки | `#181920`, рамка `rgba(255,255,255,.06)` |
| Бренд-акцент (CTA, прогресс, активный таб) | Lavender `#B8A6FF` |
| «Keep / Best pick» (только оно) | Lime `#D4F563` |
| «Trash / Delete» | Coral `#FF5A5A` |
| Вторичный текст | `#8A8F9E` (на мелком тексте `#A9AEBB`, контраст ≥ 4.5:1) |

Правило ролей: лайм **только** для «оставить / лучший кадр», лаванда — всё остальное брендовое, коралл — удаление. Цвета не смешиваем по смыслу.

### 2.2 Типографика и «растягивающиеся буквы»
- Шрифт: Plus Jakarta Sans (500–800).
- **SWIIIIPE:** на экране свайпа слово растёт по числу «I» пропорционально длине жеста (n = 1 + ⌊|dx| / 14⌋, максимум 10); цвет слова: нейтральный → коралл (влево) / лайм (вправо).
- **CLEAAAN:** при отправке в корзину слово меняется на CLEAAAN, буквы идут волной (0.7 с, сдвиг 70 мс на букву), затем возврат к SWIPE (≈1.1 с).
- **SCAAAANING** (экран скана), **KEEEEP ONE** (ревью групп), **SWEEEP PRO** (paywall) — тот же приём, мягкая зацикленная волна.
- Анимации уважают системную настройку Reduce Motion (статичная версия).

### 2.3 Паттерны
- Стекло: `backdrop-filter: blur(12px)` для плашек и нижнего дока.
- «Стопка кадров» для групп: 2 нижние карточки того же размера, повёрнуты −6° / +4°, сдвинуты на 4–6 px, полупрозрачные с рамкой `rgba(255,255,255,.16)`; бейдж `×N` и `save X MB` — подтверждение, что это группа.
- Овальное кольцо хранилища с glow, гигантская цифра «14.2 GB».

### 3.1 Навигация и поведение тапа
- Нижний док: Clean · Swipe · Tools · Trash.
- Тап по плитке **группы** (дубли, похожие, похожие видео) → Group pager с позиции этой группы.
- Тап по плитке **одиночного файла** (скриншоты, размытые/тёмные, чат) → сессия Swipe, начиная с этого файла.
- «See all» → All groups; «Swipe» в заголовке секции → Swipe по категории.
- Долгое нажатие по плитке → быстрый просмотр в шторке (пост-MVP).
- Sort каруселей: по выгоде (экономия места) убывающая.

## 4. Стек и архитектура

- **UI:** Flutter (iOS + Android), Riverpod, go_router.
- **Analysis Core:** Rust (`core/`), FFI в Dart. pHash/dHash/aHash, Laplacian, median brightness, Hamming, SHA-256, группировка: по временному окну (скользящее окно по времени съёмки) и глобально через multi-index hashing (r+1 сегментов по 64 бита; BK-tree на 64-битных хэшах при радиусе 8 оказался слишком медленным: ≈44 с на 50k против 0.27 с).
- **Platform layer:** Kotlin (MediaStore, `createDeleteRequest`, WorkManager/foreground service) и Swift (PhotoKit, `performChanges`, `BGProcessingTask`) через Pigeon.
- **Storage:** SQLite (Drift): `assets`, `hashes`, `groups`, `group_members`, `decisions`, `trash`, `scan_state`.
- **Репозиторий:**
  ```
  sweeep/
    core/       Rust-ядро + тесты
    app/        Flutter (UI, domain, data)
    app/pigeon/ контракты Pigeon
    docs/
  ```

### 4.1 Конвейер сканирования
```
Enumerate (id, size, dates, dims, duration, bucket)
  → diff against index (new / changed / removed)
  → Stage 1: metadata classification (screenshot, screen rec, chat, video)
  → Stage 2: thumbnail 64–256 px → aHash/dHash/pHash, Laplacian, brightness
  → Stage 3: candidates (time windows, size/duration buckets, BK-tree)
  → Stage 4: confirm (SHA-256 for exact dups, Hamming threshold for similar)
  → Grouping + best-pick scoring → persist → stream to UI
```
Требования: батчи, изоляты, чекпоинты, отмена, пауза по заряду/нагреву, дельта-скан.

## 5. Модуль 1: Media Grouping Engine

| Категория | Алгоритм |
|---|---|
| Duplicates | Размер → SHA-256 (поблочно, ранний выход) + совпадение EXIF-времени |
| Similar Photos | pHash (+dHash для подтверждения), Hamming ≤ порога (старт 8/64, конфиг), окно ≤ 5 с для серий; гистограмма как доп. фильтр |
| Similar / Other Screenshots | Тип медиа ОС, префиксы имён, папка Screenshots, размеры экрана; похожие — pHash |
| Similar / Other Screen Recordings | Имя/папка, пропорции экрана; похожие — ключевые кадры + длительность |
| Similar / Other Videos | Длительность ±2%, разрешение, близкое время, pHash 3–5 ключевых кадров |
| Chat Photos | Папки Telegram/WhatsApp/Viber/Messenger/Signal, шаблоны имён (Android); iOS — только по метаданным |
| Other / Strange | Низкое разрешение, повреждённые, Laplacian variance < порога, медианная яркость < порога |

Best-pick: резкость (Laplacian) → экспозиция (без клиппинга) → разрешение → размер. Пороги в конфиге, покрыты тестами на эталонных наборах.

## 6. Модуль 2: Swipe + Trash
- Навигация год → месяц с количеством и объёмом.
- Свайп влево = в корзину, вправо = оставить, Undo последнего действия, предзагрузка следующих N карточек.
- Корзина — «мягкая»: таблица ID с пометкой, оригиналы не копируются; хранение решений 30 дней (настраиваемо); «Delete forever» — один пакетный системный вызов.
- Safe Delete Preview перед очисткой: «N files · X MB».

## 7. Модуль 3: Tools (MVP)
- Генератор синуса 165–200 Hz с пульсацией (частота, паттерн, таймер).
- Sound Test: L/R канал, sweep, бас, высокие.
- Предупреждение о громкости; не обещать результат.

## 8. Вне MVP
Email Cleaner (IMAP/OAuth, верификация Google), App Cleaner (Android UsageStats), Large Files Finder, Storage Compression, Duplicate Contacts, Battery/Charging, Storage Treemap, Metadata Hygiene, Cleanup Sessions/Streaks, долгое нажатие-превью. Монетизация: решение отложено, в архитектуре `EntitlementService` (интерфейс-заглушка).

## 9. Разрешения и платформенные ограничения

| | Android | iOS |
|---|---|---|
| Медиа | `READ_MEDIA_IMAGES/VIDEO` (13+), частичный доступ (14+) | PhotoKit Full Access; при Limited — предупреждение |
| Удаление | `MediaStore.createDeleteRequest` | `PHAssetChangeRequest.deleteAssets` (в «Недавно удалённые») |
| Фон | Foreground service + WorkManager | `BGProcessingTask` (скан в основном при открытом приложении) |
| Chat-папки | Через bucket в MediaStore | Недоступны, только эвристика по метаданным |

## 10. Нефункциональные требования
- Первичный скан 50k ≤ 15 мин (цель), дельта ≤ 1 мин; пик памяти ≤ 300 МБ.
- UI ≥ 60 fps на свайпах, холодный старт ≤ 2 с.
- 0 false-positive для точных дубликатов; похожие — всегда с подтверждением.
- Privacy Manifest / Data Safety: «данные не собираются». RU/EN локализация.
- Доступность: контраст ≥ 4.5:1, цель касания ≥ 44 px, Reduce Motion.

## 11. Тестирование
Unit (golden-наборы: поворот, ресайз, рекомпрессия, кроп), fuzz (повреждённые файлы, HEIC/Live Photo/GIF), perf-бенчмарки 50k/100k, ручной «real-walk» на реальных устройствах перед релизом.

## 12. Риски
Ложные «похожие» (порог + подтверждение + Undo); батарея/время скана (инкрементальность, пауза); ограничения фона iOS; Limited Photos; отклонение в сторе («водоочистка», клинер) — честные формулировки.

## 13. Roadmap

**Фаза 0 — Фундамент (сделано, кроме сборки Flutter).** Репозиторий `sweeep/`. Rust-ядро (aHash/dHash/pHash/Laplacian/SHA-256/группировка) — 30 тестов зелёные; 50k миниатюр 128×128 (pHash + Laplacian) ≈ 3.7 с, группировка 50k: окно 5 с ≈ 16 мс, глобально (multi-index hashing) ≈ 0.27 с. Flutter 3.47.7 установлен в `D:\tools\flutter`; Drift-схема, контракты Pigeon, токены темы: `flutter analyze` без замечаний, 3 теста зелёные (в т.ч. Drift in-memory с каскадным удалением). Debug-APK собран, установлен через adb и запущен на Samsung SM-S911B (без ошибок в logcat). **Не проверено:** iOS (нужен Mac), реальный доступ к медиатеке (Фаза 1).
**Фаза 1 — Доступ к медиатеке и индекс (Android: частично сделано).** Сделано и проверено на SM-S911B: onboarding и системный диалог разрешений, энумерация через MediaStore (10 658 файлов за 2.2 с), дельта-индекс в Drift (повтор 0.2 с), серые миниатюры 128 px (~22 ms/шт). Дальше (1b, сделано): FFI к Rust-ядру на Android (arm64), хэширование всех миниатюр с чекпоинтами: 10 658 файлов за 34.5 с, возобновление после kill проверено (2 432 → дальше), 771 burst-группа по pHash ≤ 8 + окно 5 с. Осталось: SHA-256 дубликаты, сохранение групп, фоновый foreground-service, экран Scan, проверка «Allow limited access», iOS (PhotoKit).
**Фаза 2 — Duplicates + Similar.** SHA-256, pHash + BK-tree, окна, Best-pick, Group pager, All groups.
**Статус Фазы 2 (Android, сделано и проверено на SM-S911B):** SHA-256 только для файлов с одинаковым размером, группы сохраняются в Drift; similar = pHash Hamming ≤ 6, окно 5 с, complete-linkage, максимум 8 в группе; 12 групп точных дубликатов (14.2 MB) и 601 группа похожих (2.2 GB) на 10 658 файлах; экраны Groups grid и Group pager (similar по умолчанию KEEP, exact — extras в TRASH); мягкая корзина без удаления с устройства. Не сделано: системное удаление (Фаза 3), iOS.
**Фаза 3 — Swipe + Trash.** Год/месяц, свайп со стопкой и растягивающимися буквами, Undo, корзина, пакетное удаление, Safe Delete Preview.
**Фаза 4 — Остальные категории + Home feed.** Screenshots, Screen Recordings, Chat, Videos, Other/Strange; Home с сворачивающимся овалом.
**Фаза 5 — Tools.** Генератор тонов, Sound Test.
**Фаза 6 — Полировка и релиз.** Perf 50k/100k (бенчмарки всего конвейера, см. раздел 10), RU/EN (тексты короткие, разговорные, без канцелярита), a11y, Paywall (после решения по монетизации), Privacy Manifest, beta, real-walk, сторы.
