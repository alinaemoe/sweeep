# Sweeep: идеи за пределами MVP

Прототипы лежат в design canvas (ссылка в CLAUDE.md): D11 Storage map, D12 Cleanup session, D13 Session done, D1 Timeline.
Всё считается локально, без ИИ и без сети.

## 1. Storage map + Quick wins (экран D11)

**Что это.** Treemap хранилища: площадь плитки = размер, красная полоса внизу плитки = сколько из этого можно безопасно убрать. Три разреза: месяцы, типы, источники. Под картой карточки Quick wins: один кластер = одна кнопка Clean.

**Где живёт в приложении.** Главная кнопка на овале «reclaimable» (сейчас Free up) ведёт сюда; вторая точка входа это пункт в Tools.

**Что уже есть в коде.**
- `assets` хранит `size_bytes`, `created_at_ms`, `media_type`, флаги screenshot/recording/chat: типы и месяцы считаются одним `GROUP BY`.
- `home_service.dart` уже отдаёт категории (screenshots, videos, blurry, chat) с count и bytes.
- Группы дублей и похожих дают reclaimable.

**Чего не хватает.**
- Источник (Camera / WhatsApp / Telegram / Downloads): в `assets` есть `chatSource`, нужен ещё признак папки (`relative_path` из MediaStore) → одна колонка.
- Reclaimable по месяцу: join `group_members` → `assets`, считать (сумма − лучшее).
- Quick wins как правила (чистые SQL-запросы, без новых алгоритмов):
  - старые скриншоты: старше 90 дней, нет в `decisions` как keep;
  - blurry/dark: порог Laplacian p10 и median brightness < 40, уже считаются;
  - chat leftovers: файл из чата, у которого есть хэш-двойник вне чата;
  - длинные screen recordings: `duration_ms` > 60 с, старше 30 дней;
  - точные дубли.
- Правило безопасности: Quick win никогда не трогает фото из `decisions = keep` и избранное. Всё идёт в soft-trash на 30 дней, как и сейчас.

**Flutter.** Treemap это `CustomPainter` или `Stack` с `AnimatedPositioned`; раскладка squarified на чистом Dart (в прототипе уже есть рабочий алгоритм, его можно перенести 1:1). Анимация: `TweenAnimationBuilder` на смену разреза, плитки морфятся между раскладками.

## 2. Swipe streak + Cleanup session (экраны D12, D13)

**Идея.** Сессия на N фото (25/50/100), цель дня, серия дней, прогресс по месяцам. Никакого ИИ: всё из таблицы `decisions`.

**Что уже есть.** `decisions(asset_id, decision, decided_at_ms)` + SwipeScreen + Timeline по месяцам. Серию дней и прогресс месяца можно считать запросами, новых таблиц не нужно:
- день засчитан, если в нём есть ≥ 1 решение (или ≥ N по настройке);
- прогресс месяца = решённые / все фото месяца;
- «заморозка» серии = одна строка в `scan_state` (ключ `streak_freeze`), даётся раз в неделю.

**Что добавить.**
1. Таблица `sessions(id, started_ms, ended_ms, goal, swept, trashed, bytes)`: нужна для итогового экрана и истории; один `INSERT` на завершение.
2. SwipeScreen принимает `goal` и показывает счётчик «12 / 50»; по достижении открывает экран итога.
3. Порядок колоды: сначала группы похожих (там самый быстрый выигрыш), потом остальное по возрастанию даты месяца, который ещё не пройден.
4. Экран итога: CLEAAAN с волной, счётчики count-up, +1 к серии, прогресс месяца до/после. Честная подпись: файлы лежат в корзине Sweeep 30 дней, с телефона уходят только после очистки.
5. Локальное напоминание (одно в день, по настройке пользователя). Без пушей с сервера, приложение офлайн.

**Что не делаем.** Рейтинги, соцсети, награды за удаление как таковое: цель в том, чтобы разобрать месяц, а не удалить побольше. Серию дают за просмотр, а не за количество удалённого.

## 3. Что придумано, но не заложено в MVP

- **Month wrap:** когда месяц разобран на 100%, короткая карточка «июнь 2026: просмотрено 389, освобождено 1.7 GB», можно сохранить как картинку. Считается из `sessions` и `decisions`.
- **Best of month:** из каждого месяца автоматически подсвечивать 5 самых резких фото (Laplacian) как «оставить навсегда». Подсказка, а не удаление.
- **Smart order в Swipe:** сначала фото с высоким шансом на удаление (размытые, тёмные, скриншоты), чтобы первые 10 свайпов приносили максимум места.
- **Недельный отчёт на устройстве:** сколько свайпнул, сколько освободил, динамика заполнения. Один экран, без сети.
- **Widget на рабочий стол (Android):** серия и «разобрать 25 за минуту». Данные из Drift.
- **Освобождение по цели:** «мне нужно 5 GB»: приложение собирает Quick wins по убыванию уверенности, пока не наберёт цель, и показывает один список на подтверждение.
- **Фото-контейнеры по событиям:** группировка по месту/времени (EXIF GPS уже есть в MediaStore) для разбора «поездка в мае» за одну сессию.
- **Сжатие вместо удаления:** для больших видео предложить пережать (нужна платформенная часть: MediaCodec / AVAssetExport).

## 4. Порядок работ (предложение)

1. Storage map без источников (месяцы + типы) и Quick wins на уже имеющихся правилах.
2. Таблица `sessions`, цель в SwipeScreen, экран итога, серия по `decisions`.
3. Источники (`relative_path`), reclaimable по месяцу.
4. Системное удаление (Phase 3: `createDeleteRequest`): без него Quick wins только перекладывают в корзину.
5. Напоминание, виджет, month wrap.

## 5. Решения владельца по D11–D13 (согласовано, не пересматривать)

Дизайн берём из прототипа 1:1, внимательно, красота важнее скорости.

- **«You can safely free» и бейдж SAFE остаются как в прототипе.** Слово «safe» не меняем, даже если оно не точное: всё уходит в корзину на 30 дней.
- **Карточки Quick wins как в прототипе,** включая «Chat leftovers: memes you already have in a chat» и «never opened since». Это такие типы файлов, а не точные утверждения. Правила для них подбираем так, чтобы по смыслу попадали мемы и пересылки из чатов (закладываем на это время). Названия и тексты не переписывать.
- **Кнопка Clean не чистит в один тап.** Она открывает наш режим просмотра (сетка с галочками или Swipe), уже отфильтрованный по этой карточке.
- **Источники (Camera / WhatsApp / Telegram / Downloads / Instagram) считаем из индекса:** добавляем колонку с папкой (`relative_path` из MediaStore) в `assets`, схема v3.
- **Напоминания и пуши ради серии делаем.** Локальные уведомления (без сервера), одно в день, время и вкл/выкл в настройках. Нужно разрешение POST_NOTIFICATIONS (просить в момент, когда пользователь включает серию, с понятным объяснением).
- Серия с «заморозкой», цель 25 / 50 / 100, экран итога с CLEAAAN: как в D12/D13.
- Порядок: Storage map + Quick wins → Session (D12) + итог (D13) → напоминания.

## 5. Month wrap: карточка «месяц разобран» (экран D14)

**Что это.** Когда в месяце просмотрено 100% фото, приложение один раз показывает итоговую карточку: сколько просмотрено, сколько освобождено, 5-6 лучших фото месяца, серия дней. Её можно сохранить картинкой.

**Зачем.** Разбор галереи это длинная скучная работа без конца. Закрытый месяц даёт ощущение «готово», причём каждый месяц отдельно, и подталкивает взяться за следующий («Next: July 2026»). Главный результат это мотивация продолжать, а не картинка для соцсетей.

**Откуда данные (всё локально).**
- просмотрено / оставлено / в корзину: таблица `decisions`;
- освобождено: `trash_items` + `assets.size_bytes`;
- лучшие фото: самые резкие из оставленных (`hashes.laplacian_var`), по одному от серии похожих;
- сессии и серия: таблица `sessions` из раздела 2.

**Правила.**
- Показывается один раз на месяц, момент: сразу после последнего свайпа месяца. Повторно открыть можно из Timeline по месяцу с галочкой.
- Экран не делится автоматически: «Save image» только сохраняет, шаринг по решению пользователя. Картинка рисуется на телефоне.
- Лайм здесь только у BEST и у «kept», коралл у «cleared», лаванда у всего остального.
- Лучшие фото это подсказка «что сохранить», а не команда удалять остальное.

**Flutter.** Карточка в `RepaintBoundary`, экспорт через `toImage()` → PNG. Анимации: count-up, всплывающие плитки, блик, как в прототипе.
